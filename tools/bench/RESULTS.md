# Blueprint-reading benchmark - runs of 2026-07-14

Four synthetic blueprints with known ground truth (generated by
`blueprints_bench.py`): a galley (2.8x4.6, two facing runs), a single-wall
(5.4x3.2, fridge at run end), an L+island (3.6x3.0) and - new in b20 -
`bp_ushape`, a reconstruction of the owner's real failing drawing
(3.2x3.76 U-kitchen, counters both side walls, bar peninsula with the
cooktop, dashed open edges, a TALL pantry unit). Each was sent through
the app's EXACT prompt + image pipeline. Score 0-100 per drawing: room
dimensions (30), wall placement Jaccard (25), appliance positions (30),
island presence + GEOMETRY (15 - an island the size of the room scores
~7/15; b19 scored presence only, so b19 numbers are not comparable).

## Reading the numbers honestly

Two-stage and single-stage tie at ~90 on this set. The two-stage win is
STRUCTURAL, not raw score: stage 2 never sees the image, so it cannot
echo the schema example out of visual confusion, and two independent
models must both fail before garbage reaches the parser. The residual
ushape errors (peninsula/pantry confusions, ~67-92) are exactly what
lib/services/plan_normalizer.dart nets: whatever the models emit, the
plan that reaches the generator has no overlapping cabinets and no
island blocking a walkway.

Re-run before changing either chain order:

    cd tools/bench
    python3 blueprints_bench.py                 # regenerate drawings+truths
    NVIDIA_API_KEY=... python3 bench_models.py  # single-stage table
    NVIDIA_API_KEY=... python3 bench_two_stage.py  # two-stage table

Free-tier hosting changes week to week (the b18 chain leader hung on
100% of calls by mid-July; nemotron-3-super timed out 4/4 in one run and
answered 4/4 an hour later) - trust a fresh run, not this file.
